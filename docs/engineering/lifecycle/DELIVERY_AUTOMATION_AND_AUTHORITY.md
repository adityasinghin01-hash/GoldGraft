# Technical delivery without hidden merchant finishing work

Status: Plan3 engineering on paper, 6 November 2026. No implementation, account change, deployment, live payment/model/worker job or agent-internal design. CURRENT means inspected existing contract; all new lifecycle states/interfaces/modules below are PROPOSED. Vendor/account/runtime qualification gates remain open.

## Selected authority design and explicit proposal change
GoldGraft executes permitted technical steps; merchant/controller provides unavoidable authority/result decisions, not command-line/deploy homework. Initial GitHub/Render readers stay genuinely read-only. Later separate Publisher App consent and host deploy capability are requested only for reviewable exact result. All tokens stay in trusted brokers. The sandbox agent cannot mutate remote source/host.

Old paper policy required controller merge externally. Proposal LC-A1 replaces that technical chore where permitted: controller approves exact result in saved GoldGraft case; trusted Apply broker performs a normal protected PR merge as its separately granted publisher identity after GitHub required reviews/checks/rules are satisfied. This is a proposed action-policy extension, not existing permission or a current implementation. Provider-level Contents/PR write remains repo-wide and disclosed; broker exact-head/base/tree/actions restrictions are service policy. No protection bypass, default branch direct push, Workflows write or automatic self-approval. If repository requires controller action in GitHub, show that single necessary action in same case, then automatically resume technical work; do not claim unattended completion in that configuration.

## Consequential-action ledger
Each publication/merge/deploy/config/cutback/cleanup action stores durable intent before call, immutable action/idempotency identity, target/expected versions, current approval/grant epoch/generation, effect class, minimal request digest, timeout/retry limits and provider receipt/query strategy. Mutation timeout -> OUTCOME_UNKNOWN; query by action/branch/PR/deploy/correlation and actual runtime before retry. Provider operations without documented idempotency require service dedupe plus reconciliation, not fabricated exactly-once guarantee. Cancellation fences local new effects; dispatched external action may still finish.

## Publish and merge build recipe (future implementation)
1. Re-fetch reviewed source head/base/current authority and full CI/host automation chain, including reusable workflows/scripts/privileged secrets/default-branch/previews. Reader cannot silently read ungranted external workflows; missing configuration is hold. Inspect before ANY branch write; a PR branch itself may deploy.
2. Bind safe trigger fingerprint to approved action. If publication could change production/expose privileged credentials, hold until an explicitly approved separate remediation is in reviewed scope; do not auto-disable user pipelines.
3. Publisher writes only exact candidate to a service review branch and creates one PR. Reconcile existing branch/commit/PR on retry. No hidden merge/deploy when reporting Published.
4. Revalidate provider rules and checks/reviews, expected head and base. Use documented merge operation with reviewed head SHA, approved method and current protection enforcement. Provider acceptance alone does not prove merged tree equals tested tree. If base/rules/head/merge tree differs, do not deploy; rebuild/prove/review exact resulting artifact or return held. First image-backed host must not auto-deploy this merge.
5. Record actual merge tree/result and compare to tested candidate/build subject. Deployment proceeds only for exact validated artifact/config. Registry artifact must be durably merchant-accessible; temporary GoldGraft-owned registry auth cannot become a permanent live dependency.

## Non-Git direct-artifact route — required alternative, no Git migration
For local-folder/cloud-file/host-export input without an approved Git destination, the service uses DirectArtifact delivery, not mandatory PR/merge. Before promising full completion, identify a merchant-controlled private source-bundle destination and supported image registry, persistent host target, pull credentials/retention and operating ownership. If none is authorised, retain a specific delivery setup hold; a local download alone is not the completed upgraded website.

Build exact tested candidate image/source bundle from immutable snapshot; record source/manifest/build/dependency/artifact provenance privately. Ask actual destination controllers for separate later minimal registry/blob publish rights and host deploy authority bound to exact result/resources. These are new destination writes, not escalation of original source read grant; local original folder remains unchanged. Never choose a public repository/registry for private source automatically. A private signed build/provenance bundle can be verified against an approved builder trust root without presuming GitHub Enterprise attestations.

Inspect registry/webhook/object automation and host image-source triggers BEFORE first artifact/bundle write, just as before Git push. Publish exact image by digest and source bundle by content-addressed authorised key, reconcile ambiguous writes, verify registry/destination digest and merchant durable pull/read rights, then perform separately approved exact-digest host deployment. No PR/merge is fabricated for this route. All state/callback/recovery/observation/finalisation/exit gates still apply. Source bundle availability and ownership are verified; optional later download by maintainer is not a required step to finish the website deployment.

Apply plan/approval explicitly selects git_protected or direct_artifact. Git route requires reviewed head/base/PR protection; direct route requires current destination/registry policy and artifact/provenance bindings, with Git fields null. Branch publication and registry publication can both be consequential; no inference that object upload is harmless. Unknown registry/write/deploy outcomes are reconciled, never blind repeated with a new identity.
