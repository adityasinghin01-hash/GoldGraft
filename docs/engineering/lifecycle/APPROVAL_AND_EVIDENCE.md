## Exact current apply approval
Approval is separate from initial read grant, Start, reviewer access and provider installation consent. Controller sees short result/scope/target/source/environment/change/impact/data and recovery summary; Details contains evidence. Required source and host controllers each approve their own action/resources, or explicit valid delegation covers both. Provider MFA/mandatory reviews remain real. Proposed approval TTL 15min, single-use for action group with current grant/epoch and target-revision checks. Expiry means refresh exact approval, not permission to change more.

Approval binds tuple: approving principal and role evidence; tenant/case/work; graph/scope; baseline/candidate/patch/build artifact; evidence bundle; current source head/base tree; CI/reusable workflows/called scripts/host preview/deploy chain; target host/environment/config/state plan; requested publication/merge/deploy/cleanup actions; budget/policy; expiry/generation and recovery strategy. No repo-wide provider permission is falsely described as branch-only. Any material byte/target/config/policy/recipient/permission change invalidates affected downstream approval; re-approve new result.

Conservative broker serialises local approval consumption/cancel/action intent, checks current controller/resource authority immediately before external action and fences stale generations. Cross-provider atomic approval is impossible: external races/in-flight outcomes are recorded and reconciled. Signed receipts verify provenance, not correctness or exactly-once effects. Lost approval response is reconciled by original action identity; no duplicate later writes.

Sources for provider mechanisms (not GoldGraft conformance): [GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches), [PR API](https://docs.github.com/en/rest/pulls/pulls). Required checks/reviews must be honoured; no bypass/admin escalation.
