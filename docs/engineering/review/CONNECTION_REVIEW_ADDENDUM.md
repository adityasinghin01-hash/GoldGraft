# Connection review addendum — effective after Plan4 review

This addendum refines the closed Plan1 authoring snapshot without rewriting its historical evidence or implying actual contracts changed. For reviewed team build documentation use Plan1 canonical connection-control proposal plus this addendum and Plan3 lifecycle interfaces. Internal agent design stays deferred.

1. **True source read-only:** qualify effective provider capability against every relevant create/update/delete/share/write path, not only whether the selected original file is writable. A viewer role on a file does not necessarily remove token ability to create other objects. Google Drive drive.file remains rejected as a hidden read-only grant; no broad Drive fallback. If no narrow genuinely read-only direct path is qualified, use explicit controller-selected local source or hold; do not claim direct integration.
2. **Observed runtime versus static inference:** deployment/provider metadata, immutable source/artifact/provenance, trusted nonsecret effective config/runtime observation and declared controller assumptions are separate facts. No provider configVersion or per-instance digest is invented. First single-instance Render profile still requires real qualification, not a generic match boolean.
3. **Generic input identity:** all source routes bind source snapshots/complete required resource graph/work package. Mandatory Git SHA or singular host fields are superseded; no snapshot descriptor creates ownership or proof the running shop uses it.
4. **Durable action semantics:** persist action intent before Start/Stop; no pre-accept worker generation required; immutable acceptance separated from current status; retry does not restart stopped/revoked work.
5. **Ownership/path reconciliation:** initial Plan1 proposed pieces/connector/ is a design decomposition, not a currently implemented piece or frozen repo allocation. Reviewed team baseline locates backend provider/authority/custody/broker/readiness/lifecycle mechanism modules under pieces/backend/connection/ and pieces/backend/lifecycle/, runtime modules under pieces/runner/, shop domain under pieces/shops and switch-libs, proof under pieces/proof, UI/agent integration under Singh's pieces/web and pieces/agents. Shared formats remain contracts/foundation. Plan2 exact deltas supersede earlier new-piece proposal; no cross-piece code imports or duplicate browser/backend authority logic.
6. **Scope and evidence labels:** non-Git/multi-host adapters remain planned until implemented and qualified. Keep historical provider-specific outside-scope dispositions and actual empirical gaps; analogues do not prove those providers served. Plan1/3 paper closure, document checks and31 abstract tests do not prove a usable/secure/live service or60-second/coverage targets.

7. **Non-Git delivery:** local/cloud/host-export source cannot be forced into Git-only head/base/PR publication. Plan3 now defines separate protected-Git and direct-artifact routes; destination write/provenance/automation/merchant ownership gates apply to private registry/source bundles before exact host deploy. Initial source read grant unchanged. LC33 captures this boundary.
