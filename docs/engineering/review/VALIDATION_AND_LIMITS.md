# Validation levels and limits

- Inspected: repository current formats/guidance/local state, proof PR handoff/evidence source, public provider docs/API schemas. Source inspection/reporting is not rerun code or payment evidence.
- Designed/reviewed: connection/lifecycle controls, exact action/effect boundaries, future slices/fixtures/failure acceptance and team delta proposals. Independent paper reviewer findings have their own record; not an external expert security certification.
- Prior abstract protocol:31 limited model tests from earlier solution study, not re-run here and not actual account/isolation/termination/payment proof.
- Current run: document/hash/link/JSON/reference verification only; no product tests, installs, account/service changes, money/model calls, worker allocation, live shop operations, merge/push/messages.
- Open: actual source completeness/correspondence, scoped grants/current controller flow, effective config/runtime identity, processor tier/region/ZDR/retention, E2B isolation/egress, durable distributed effects/cancellation, actual sandbox auth/payment/legacy continuity, production release/exit and real users/accessibility/convenience/coverage.

No evidence supports70%/90% reach, under-one-minute effort or guaranteed downtime/cutback/financial recovery. Non-Git/multi-host route architecture is extensible but additional adapters are unimplemented/unqualified. Selected Render account exists by user report; scoped beta/metadata/action availability not established. API docs alone cannot qualify these gates.

Plan4 resolves paper contradictions and classifies residuals by build/design/implementation/account/release/user requirement, not by making every gate green. Changes to protected publication/merge authority are proposals requiring exact consent; no initial source grant escalation. Actual agent internals remain deferred.
