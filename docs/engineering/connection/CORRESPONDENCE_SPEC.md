# Source, deployment and current shop correspondence

Status: paper engineering specification, 6 November 2026. Nothing here is a deployed feature or current API unless explicitly labelled CURRENT. Proposed components/interfaces require later implementation and contract approval. Plan 1 ends at verified first sandbox operation; agent internals and Plans 2–6 remain outside scope.

Decision T07: first qualified Render path is digest-pinned image-backed PHP reference with build provenance and a trusted runtime identity envelope. General Git-backed PHP correspondence is not certified by `commit.id` alone. A controlled reference image/runtime marker must be built and qualified later; absent in current sample.

Required evidence chain, all private by default:
A. Reader repo_id + full source commit + source manifest hashes, acquired under controller binding.
B. Build provenance: approved builder identity and exact workflow revision, source materials (including pinned base/package dependencies), build config, full source manifest and OCI linux/amd64 image digest. Verify signature/trust root and subject/material equality locally. A self-declared image label is not provenance. Retrieve bundle as bounded signed sidecar through source Contents read or authorised public registry; never broaden Reader writes. Build provenance generated in the later authorised shop-build pipeline, not preflight.
C. Render service owner/workspace, selected service/environment, image.ref and current live deploy image.sha equal that digest; inspect actual deployment override, not settings alone. All active instances/rollout must represent one qualified version; pending deployment or ambiguous status holds.
D. Config/dependency manifest: nonsecret values fingerprinted, secret references/required names only, code outside image forbidden, writable data only under isolated declared directories; callback/return routes and flat-file schema accounted for. No reading production data or secret values. Missing effective config visibility is a hold, not a skipped check. Controller confirms no manual shell mutation; future controlled reference must disable/restrict runtime mutation and separately qualify this operating assumption.
E. Bounded HTTPS public challenge to the reference's trusted runtime identity endpoint, returning nonce, build/source/image identifiers, config-version and signature; provider route/custom-domain metadata connects it to selected service. This endpoint is PROPOSED, not currently in the sample. Key kept by trusted wrapper, no exposure to model/shop code. Its signature authenticates the wrapper statement, not every mutable filesystem byte. Attacks by privileged host/controller are outside this proof's trust assumptions; if those assumptions cannot hold, correspondence remains unverified.
F. Re-read current deployment/config version after challenge. Change between reads invalidates the chain. Store explicit provider-reported versus observed versus controller-attested fields; never compress them into a single unexplained green version_match.

TTL: 5min initial evidence freshness; Start rechecks current live deploy, service updatedAt, grant/binding/policy and known source revision. Cheap unchanged checks may reuse large snapshot only when digest chain still matches. Repo branch advancing invalidates readiness and requires user scope refresh; never silently move pinned revision. Already accepted runs keep pinned source but pause privileged work on revoked authority or environment drift. Do not treat mutable tags, matching HTML, DNS control or GitHub deployment status as exact source proof.

Public fetch policy: HTTPS only first path, public IPs only including IPv6 rules, revalidate every redirect/DNS/connect, no private/link-local/metadata destinations, bounded response and no ambient cookies. Deploy-hook URLs are forbidden even when GET. No live checkout/crawl that might create orders. First shop must expose a known side-effect-free identity route; other sites get static URL-only draft until supported.

Future acceptance must test wrong domain/service/env, old live deploy despite new build, tag drift, forged/replayed marker, bad provenance, changed config, mismatched callback backend and writable code overlay. If any link absent: Match not verified; no full-scope Start. This design is correspondence under explicit trust assumptions, not independent byte-by-byte forensic attestation of a server.

## Non-Git correspondence
A source snapshot need not have a Git commit. For local/cloud/host-export routes bind actual capture/provider revision-set and content manifest to a qualified artifact/runtime chain. Files received is a separate state from files match running shop. A controller-supplied folder cannot bypass provenance/current-runtime checks; static source availability alone never makes full Start ready. See FIXED_JOURNEY_AND_SOURCE_ROUTES.md.
