# Model processing and retention gate

Status: paper engineering specification, 6 November 2026. Nothing here is a deployed feature or current API unless explicitly labelled CURRENT. Proposed components/interfaces require later implementation and contract approval. Plan 1 ends at verified first sandbox operation; agent internals and Plans 2–6 remain outside scope.

Decision T08: service-owned Anthropic commercial Messages API through a trusted gateway; no consumer Claude session, Workbench, file upload, hosted tools, remote web search, batch/prompt cache or automatic provider fallback. Initial gateway candidate `claude-sonnet-5-5` is a provider-documented model ID, not a choice of agent algorithms. Deployment must verify model availability, applicable retention class and resolved version/behaviour before allowlisting it; any change invalidates processing-policy binding. If unsuitable, gate remains closed rather than substituting a model silently.

Published commercial terms support a default no-training commitment subject to their conditions. General API retention is not zero; feature/model-specific arrangements can differ. This design requires actual eligible organisation/model ZDR evidence and approved region/processor/subprocessor/support-access disclosure before source egress. No account entitlement or DPA was obtained here. Do not promise a 24h deletion of provider copies under a standard longer-retention account. Required single-region processing remains unverified; hold if the merchant's constraint cannot be met.

Gateway receives case/job/generation/policy/model allowlist, minimised source excerpts and allowed task context. Authenticate worker capability; recheck Start, current delegation/expiry, budget and destination policy; scan secrets/customer data at final outbound boundary; reject unapproved data classes and oversize payload. Provider key stays in gateway vault. Untrusted text cannot add tools, recipients, endpoints or retention exceptions. Gateway returns schema-validated untrusted data, not authority. Tool execution remains deterministic broker policy and agent internals remain unspecified.

Do not log prompts/responses by default; audit payload manifest/hash, model ID, token/budget accounting and policy decision without recoverable secret contents. Only necessary redacted outputs enter evidence under case access. Disable optional retention-bearing features until separately assessed. Provider error -> retry bounded only if request semantics allow; unknown provider outcome consumes conservative budget and is recorded, never declared deleted.

Acquisition disclosure before source read: code is copied to GoldGraft trusted quarantine/work storage and later approved runtime; named regions/providers/recipients/retention and limits visible. Start separately authorises this model-processing scope. Since execution vendor also receives the full approved snapshot, its DPA/region/log/snapshot retention is a separate gate; model ZDR alone is insufficient. Case identity data processor and review storage also appear in the subprocessor register.
