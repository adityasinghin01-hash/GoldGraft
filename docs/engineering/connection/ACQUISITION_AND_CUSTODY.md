# Acquisition and source custody

Status: paper engineering specification, 6 November 2026. Nothing here is a deployed feature or current API unless explicitly labelled CURRENT. Proposed components/interfaces require later implementation and contract approval. Plan 1 ends at verified first sandbox operation; agent internals and Plans 2–6 remain outside scope.

Decision T06: bounded HTTPS archive fetch at full immutable commit, streamed to quarantine; no Git hooks, checkout execution, package scripts or submodule recursion. Broker authorises exact case/resource/revision/recipient binding and policy before every fetch; validates current provider access. Quarantine is encrypted service storage in a named configured region; first deployment policy selects US service storage and E2B US execution conditionally, disclosed before grant; no claim of exclusive US model processing without processor evidence.

1. Reject arbitrary acquisition URL; derive archive from provider/resource ID. Follow only documented approved archive redirect chain with DNS/IP/HTTPS validation and stripped cross-origin credentials.
2. Enforce 1 GiB decompressed source cap, 100k files, 32 path depth, 255-character component, 100:1 expansion cap, 5min acquisition timeout as proposed initial limits. Abort and delete incomplete copy on limit; no Ready.
3. Extract in fresh root using descriptor-relative no-follow operations; reject absolute/parent paths, links (including hardlinks), devices, FIFOs, duplicate/case-colliding names and overwritten entries. Enforce limits while streaming, not after extraction. Parsing occurs in constrained trusted parser process, not control plane unrestricted file operations.
4. Produce original manifest (path/type/size/hash), then destination-specific exclusion manifest. Exclude .git/history, .env/key/cert stores, customer exports, uploads/databases/order state and large irrelevant binaries. Secret signatures plus entropy/context and known fixture allowlist identify suspect content; any unresolved suspected secret quarantines the file and blocks affected scope. Scanner cannot guarantee absence. Embedded non-removable essential secrets require controller remediation, no model override.
5. Work snapshot contains approved source only; preserve original content hashes plus transform/omission report. No silent source rewrite to bypass limits. Submodules/LFS/private dependencies are first-path unsupported unless each resource gets independent grant/provenance; otherwise hold. No production data clone.
6. Source retrieval before Start is permitted only under disclosed read/acquisition consent; model egress/executable work needs Start. Raw code is accessible only to trusted acquisition service, explicitly authorised reviewer projection and isolated worker as required; support access exceptional, audited and separately authorised.

Storage: random tenant/job keys, envelope encryption with KMS, per-service IAM; no public bucket or guessable capability URL. Download URLs private/authenticated and short lived; logs record hashes/counts, not source/credentials. Quarantine does not enter diagnostic backup. Work/review exports require membership and controller-approved recipients; public claims have separate redacted projection.

Retention policy targets: acquisition max 7 days; raw copy 24h after terminal state or at max, whichever earlier; redacted review 30 days; requested active delete 24h and backup expiry 30 days. These are designed targets, not enforced here. Expiry fences new work, requests termination then deletes copies; do not keep running beyond expiry. Hash/receipt metadata retained 30 days initially. Legal holds must be explicit. Processor retention separately tracked; exported third-party copies may be unrecoverable. Stop, revoke and delete are different operations. Full post-upgrade exit is deferred Plan 3.
