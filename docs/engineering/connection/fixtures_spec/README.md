# Synthetic fixture and stand-in specification

Status: paper engineering specification, 6 November 2026. Nothing here is a deployed feature or current API unless explicitly labelled CURRENT. Proposed components/interfaces require later implementation and contract approval. Plan 1 ends at verified first sandbox operation; agent internals and Plans 2–6 remain outside scope.

These describe files to create during authorised implementation under fixtures/connection_control/, not application fixtures generated by Plan1. Use source labels in companion index to preserve strict no-extra-field schemas.

| Fixture group | Exact values/mutations and expectations |
|---|---|
| actors.json | tenant_A/tenant_B; owner_A, source_admin_A, host_admin_A, reviewer_A, unauthorised_B. Same email string alone never merges provider principals. Role grid includes reviewer Start denial. |
| binding_pending.json / binding_approved.json | Same case and exact requester/shop/repo/service/env/recipients; only approved relation may expose private source. Mutate recipient or env without epoch -> deny. |
| render_read_grant.json / render_classic_grant.json | Services/Deploys/Workspaces Read, secrets/Run/write denied versus unqualified classic capability. No real token; fake vault handle only. Provider user/member/admin and inactive/wrong-user responses. |
| render_live_digest.json / render_pending_digest.json | live deploy D1 image.sha H1, pending D2 H2; service.imagePath may differ. Correspondence must use D1 actual live identity, not most recent list item. |
| provenance_valid.json / provenance_wrong_subject.json | Trusted builder/workflow/source C1, OCI subject H1 versus H2 mismatch; signatures generated with explicit synthetic test key, never production identity. |
| runtime_nonce.json | Nonce N1 bound to service/config/source; stale N0/wrong config rejected. Clearly synthetic wrapper; no assertion endpoint already exists. |
| archive_cases/ | Relative safe file; ../escape, absolute, symlink/hardlink, FIFO, duplicate/case collision, expansion/depth/count breach. Use bounded small deterministic representations, not uncontrolled zip bomb. |
| secrets/ | Invented canary `SYNTHETIC_NOT_A_REAL_KEY`, customer/order dummy records, credential-like strings in .env/PHP/binary and expected omitted manifests. Never real credentials/data. |
| start_races.json | ordered traces: stop→start, start→stop, commit→lost response→retry, duplicate dispatch→lease expiry→late operation; exact expected work ID/generation/status/event seq. |
| operation_claim_only.json / operation_verified.json | Same assignment but no operation versus trusted digest read; only latter may emit OPERATION_STARTED. Invalid signature/scope/generation denied. |
| policy_missing.json / policy_qualified.json | Unverified account facts versus synthetic eligibility receipt; fake cannot qualify actual processor. |
| retention_states.json | active, expiry fence, stop pending, deleted-active, backup-pending, exported-unrecallable, legal-hold; never collapse into deleted. |

Stand-in providers return fixtures and record allowed/denied calls. Fake worker can emit claim without operation to catch false Started; fake processor records canary leakage attempts without network. Offline fixtures reproduce boundary semantics only, not real provider signature/auth/isolation. Each fixture index names source/evidence class and AC IDs. Existing PayPal synthetic response shapes retain official sources and integer minor money; do not invent provider fields.
