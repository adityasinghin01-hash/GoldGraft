# Identity, sessions and controller binding

Status: paper engineering specification, 6 November 2026. Nothing here is a deployed feature or current API unless explicitly labelled CURRENT. Proposed components/interfaces require later implementation and contract approval. Plan 1 ends at verified first sandbox operation; agent internals and Plans 2–6 remain outside scope.

Decision T04: WorkOS AuthKit hosted identity, Magic Auth email code, with GoldGraft server-side opaque session and case authority. This deliberately replaces the earlier email-link-only suggestion: WorkOS documents email-link scanner problems and offers codes. One code entry is preferable to falsely promising a reliable one-click link. AuthKit proves contact identity only. WorkOS account, allowed redirect and email delivery remain unconfigured.

[Provider identity mechanism](https://workos.com/docs/authkit/modeling-your-app). Provider SDK/version must be pinned when implementing; no library installed here.

Proposed session policy: 256-bit random opaque identifier hashed in Postgres; __Host- cookie, Secure, HttpOnly, SameSite=Lax, Path=/, no Domain; session 12h absolute/30min idle; rotate at login/privilege change, revoke on logout. BFF retains provider access/refresh tokens encrypted, never browser storage. CSRF token plus Origin checks on mutations. These are initial policy choices requiring later usability/security checks, not vendor defaults. Authenticate provider code with server SDK and verify issuer/audience/redirect/nonce as applicable.

Draft: server creates random draft ID and browser-bound draft secret, anonymous TTL 24h; stores URL only, no private probe. On login compare hashed draft secret and claim atomically to authenticated principal; never claim by case ID in URL. Phone login cannot automatically claim a different browser draft: authenticated resume may use a one-use browser transfer code and require original association; never leak draft by matching email. Draft claim conflict preserves original owner and explains recovery generically.

Case membership roles: requester (own metadata/status; Start only after explicit delegation); source controller; host controller; reviewer (scoped read evidence only). Service support has no ambient source access. Identity provider organisation membership is not shop authority. Connectors store immutable provider account/resource IDs and fresh roles; controller must show current provider resource administration/owner authority sufficient to grant association, not merely read collaboration access. Where provider cannot prove this, require provider-owner approval; do not infer from key possession.

Invite: random 256-bit token stored hashed, 24h TTL, case + intended contribution only; copied by requester into their channel, no automatic messages. GET shows generic request, no private repo/service findings. After independent login/resource authority, controller sees requester identity, entered shop, exact resource/environment and named recipients. POST approval consumes invite and records binding version; deny/no response discloses no source. Forwarding does not transfer disclosure authority. Recipient additions invalidate binding and require that controller's approval before new access; separate source and host controllers approve their own data.

Callback continuation: one-use random state stored hashed, provider/action/case/session/principal/redirect target plus 10min TTL. Provider return is validated before consuming; wrong attempts cannot consume rightful state. Resume target is internal allowlist. Login session rotation uses server-side continuation ownership mapping; no unauthenticated client selects case ownership. PKCE where provider supports it. MFA/SSO/approval holds retain saved case. Resend rate-limited with generic responses; no email existence or cross-tenant case enumeration.

Failure rules: session expiry freezes browser access, not automatically a durable accepted worker; revoked case/grant blocks further privileged work. Reviewer Start denied; revoked session cannot refresh itself; deleted/rejected binding cannot resurrect on reinstallation. Case metadata status projection must be authorised at read time. WorkOS invitations never substitute for controller binding.
